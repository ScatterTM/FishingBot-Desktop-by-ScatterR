Fishingbot v2.7.0 patch 51 - Database manager app in the desktop hub (2026-11-08)

- Not included: creating new entries, deleting entries, and editing object keys (only the values of existing keys).
- Numbers are written back as JSON numbers, so integers above 2^53 lose precision on save.

Fishingbot v2.5.0 — Safe in-place installer update and repair (2026-11-01)
- Installer automatically discovers the existing install directory from the current Fishingbot uninstall registry entry, legacy Inno Setup registry entries (including 32-bit machine entries), or the documented per-user default path.
- Existing installs are updated/repaired in place; the legacy Inno Setup uninstaller is no longer executed during migration. Its old uninstaller files and registry entry are retired only after the new files, shortcuts, manifest and uninstall registration are installed.
- Added an app-owned install manifest. Future releases overwrite/update all packaged files, add newly packaged files, and remove obsolete files listed by the previous Fishingbot manifest. Unknown files from pre-manifest installations are preserved rather than guessed to be disposable.
- Before an update/repair, the installer creates a private per-user ZIP backup containing `.env`, the complete `data\` tree, existing app files that will be overwritten/removed, the previous manifest, legacy cleanup targets and old Inno uninstaller files. Keeps the three newest successful pre-update backups under `%LOCALAPPDATA%\Fishingbot\UpdateBackups`.
- Added rollback: if file copying, settings migration, manifest writing, shortcut creation or uninstall registration fails, newly introduced payload files are removed and the backup restores overwritten program files, `.env` and data files.
- Setup refuses to downgrade a newer installed version, refuses to overwrite a non-empty unrecognized folder, and uses a tracked registry install path to avoid accidentally installing beside an existing copy.
- Setup waits for Fishingbot and its local server to close cleanly. It no longer kills the SQLite-owning server during an update; if shutdown cannot be confirmed, setup aborts before backing up or replacing files.
- Existing `.env` is preserved, including its custom `FISHINGBOT_EXTENSION_RELAY_URL`; only the currently managed Twitch Client ID, selected port/local origin and known retired hosting keys are migrated. The previous `.env` is included in recovery backup.
- The installer retains `data\` wholesale, including `fishing.sqlite`, SQLite sidecars, loot table, local admin data, Twitch token stores and `extension-master-admin.json`. The deprecated `data\public-hosting` folder is no longer deleted during update.
- Uninstall keeps data and recovery backups by default; the explicit delete-data option also removes update recovery archives.
- Hardened install discovery to include both current-user and machine 32-bit/64-bit registry views; a generic empty `data` directory is no longer enough to classify an arbitrary folder as Fishingbot.
- Added an explicit release-payload guard: `.env`, `data/`, logs, backups and the install manifest are rejected if included in the installer payload, preventing accidental overwrites of user data.
